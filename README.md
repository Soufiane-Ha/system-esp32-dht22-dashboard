# مشروع مادة: Développement d'applications IoT
## نظام مراقبة درجات الحرارة والرطوبة باستخدام ESP32 و DHT22 عبر وسيط MQTT

---

## 📌 1. فكرة المشروع والهدف منه

يهدف هذا المشروع التطبيقي (TP) إلى بناء منظومة متكاملة لإنترنت الأشياء (IoT System) تعتمد على معمارية **النشر والاشتراك (Publish / Subscribe)** عبر بروتوكول **MQTT**:

1. **عقدة الاستشعار (ESP32 + DHT22)**: تقوم بقراءة درجات الحرارة والرطوبة ونشرها (Publish) بصيغة JSON عبر البروكر.
2. **وسيط الرسائل (MQTT Broker)**: يستقبل الرسائل ويوجهها للمشتركين (يدعم تشغيل محلي 100% دون إنترنت أو سحابي عبر EMQX).
3. **جهاز الاستقبال والوسيط (Intermediate Receiver / Edge Gateway)**: يستقبل البيانات الخام، يقوم بمعالجتها وحساب مؤشرات إضافية (مؤشر الحرارة المحسوسة Heat Index ونقطة الندى Dew Point)، يفحص عتبات الإنذار (Thresholds)، ثم يعيد إرسالها إلى شاشة العرض.
4. **شاشة العرض ولوحة التحكم (Dashboard PC)**: واجهة ويب عصرية تفاعلية تعرض القراءات الحية، العدادات، المخططات البيانية اللحظية (Chart.js)، سجل الحزم المباشر، وأزرار التحكم عن بعد في جهاز ESP32.

> **💡 ملاحظة هامة:** نظراً لأنك تعمل بمفردك على نفس الحاسوب، تم تصميم النظام ليعمل بكامل مكوناته في بيئة محاكاة واقعية على جهاز واحد، مع توفير الكود الكامل المخصص لرفعه على لوحة ESP32 الحقيقية متى أردت.

## 🚀 4. طريقة التشغيل السريعة على حاسوبك

### الطريقة الأولى: العرض الاحترافي في 4 نوافذ مستقلة (الأفضل لتقديمه للأستاذ)

فقط اضغط نقراً مزدوجاً على الملف:
👉 **`start_multi_windows.bat`**

سيقوم بفتح 4 نوافذ منفصلة بالتوازي ويفتح المتصفح تلقائياً:
1. **نافذة 1 (البروكر)**: تعرض اتصالات العملاء والرسائل المارة.
2. **نافذة 2 (خادم الويب)**: يخدم لوحة التحكم على `http://localhost:3000`.
3. **نافذة 3 (المستقبل Gateway)**: يعالج الحزم ويحسب المؤشرات ويظهر تنبيهات الخطورة.
4. **نافذة 4 (محاكي ESP32)**: يبث درجات حرارة ورطوبة واقعية كل 3 ثوانٍ.

---

### الطريقة الثانية: التشغيل بأمر واحد في الطرفية (Terminal)

افتح موجه الأوامر في مجلد المشروع واكتب:
```bash
npm start
```
أو عبر السكربت المخصص:
👉 **`start_all_together.bat`**

ثم افتح متصفحك على الرابط:
👉 **`http://localhost:3000`**

---

### الطريقة الثالثة: تشغيل كل جزء بمفرده يدوياً

| المكون | الأمر | الوظيفة |
|--------|-------|---------|
| **البروكر المحلي** | `npm run broker` | يشغل وسيط MQTT على المنافذ 1883 و 8888 |
| **خادم لوحة التحكم** | `npm run server` | يشغل خادم الويب على المنفذ 3000 |
| **المستقبل والمعالج** | `npm run gateway` | يستقبل البيانات، يحللها، وينشر النتائج |
| **محاكي الـ ESP32** | `npm run simulator` | يولد ويبث بيانات حساس DHT22 |

## 🎮 5. سيناريوهات التجربة والعرض أمام الأستاذ (Demo Scenarios)

أثناء تشغيل محاكي الـ ESP32 (`simulator/esp32_simulator.js`)، يمكنك الضغط على المفاتيح التالية لاختبار التفاعل الحي:

- **اضغط على حرف `t`**: لمحاكاة موجة حرارة مرتفعة مفاجئة (**38°C**):
  - ستلاحظ فوراً إطلاق **إنذار باللون الأحمر** على شاشة العرض.
  - سيصدر المتصفح **صوت صفارة إنذار حية** (Web Audio Chime).
  - ستقوم الـ Gateway بتسجيل حالة **CRITICAL** وإرسال إشعار فوري.
- **اضغط على حرف `h`**: لمحاكاة رطوبة خانقة فائقة (**90%**).
- **اضغط على حرف `n`**: للعودة فوراً للظروف الطبيعية المستقرة (**24.5°C** و **55%**).
- **من لوحة التحكم في المتصفح**: اضغط على أزرار التحكم `💡 تشغيل ليد ESP32` و `🔌 إطفاء ليد ESP32` لتوضيح الاتصال ثنائي الاتجاه (Bi-directional MQTT).

## 🔌 6. ربط وتشغيل لوحة ESP32 الحقيقية مع حساس DHT22

إذا أردت الانتقال من المحاكي إلى العتاد الحقيقي:

1. قم بتوصيل حساس DHT22 بـ ESP32:
   - **VCC** ➔ **3V3** في ESP32
   - **DATA** ➔ **GPIO 4** في ESP32
   - **GND** ➔ **GND** في ESP32
2. افتح ملف الكود المرفق: `esp32_firmware/esp32_dht22_mqtt.ino` بواسطة **Arduino IDE**.
3. عدل اسم شبكة الواي فاي وكلمة المرور:
   ```cpp
   const char* ssid = "اسم_الشبكة";
   const char* password = "كلمة_المرور";
   ```
4. ارفع الكود إلى اللوحة وافتح شاشة العرض: ستستقبل لوحة التحكم البيانات مباشرة من الحساس الحقيقي!

*(راجع الدليل المفصل في `esp32_firmware/WIRING_AND_SETUP.md` لمزيد من التفاصيل).*

## 🧠 7. أسئلة متوقعة من الأستاذ وأجوبتها النموذجية

### س: لماذا نستخدم بروتوكول MQTT بدلاً من HTTP في إنترنت الأشياء؟
- **ج**: لأن MQTT مصمم خصيصاً للأجهزة محدودة الموارد وشبكات الاتصال الضعيفة:
  1. حجم الترويسة (Header) في MQTT صغير جداً (يبدأ من 2 بايت) مقارنة بترويسات HTTP الكبيرة.
  2. يعتمد على اتصال دائم ومستمر (Persistent TCP Connection) دون الحاجة لإعادة المصافحة (Handshake) في كل قراءة.
  3. معمارية Publish/Subscribe تفصل تماماً بين المنتج (Publisher) والمستهلك (Consumer) عبر وسيط (Decoupling).

### س: ما هي فائدة الوسيط/المستقبل (Intermediate Gateway) في المعمارية؟
- **ج**: يمثل مفهوم **الحوسبة الطرفية (Edge Computing)**؛ فبدلاً من إرسال البيانات الخام مباشرة للعرض أو السحابة، يقوم المستقبل بالتحقق من جودة البيانات، حساب المؤشرات المشتقة (مثل Heat Index)، تصفية الضوضاء، وفحص شروط الخطر محلياً لاتخاذ رد فعل فوري حتى لو انقطعت السحابة.

### س: كيف تتصل صفحة الويب (HTML/JS) بوسيط MQTT؟
- **ج**: المتصفحات لا تدعم فتح اتصالات Raw TCP sockets، لذلك يدعم البروكر خاصية **MQTT over WebSockets** عبر المنفذ 8888 محلياً أو 8084 سحابياً، مما يسمح لكود JavaScript في المتصفح بالاشتراك واستقبال الرسائل لحظياً.
